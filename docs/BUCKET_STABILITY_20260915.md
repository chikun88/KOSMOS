# 固定バケツ周辺の後戻り対策（2026-09-15）

この文書は最初の一律減速案の記録です。速度維持の要望を受け、
現在は[通過判定と曲がる区間だけの減速](BUCKET_FAST_STABILITY_20260915.md)へ更新しています。
以下の設定・検証値は更新前のものです。

## 記録で確認した原因

実機記録 `20260914T223835.819202Z-4d88282e` の右フィールドで、
固定バケツ間の中継点を通過判定の半径0.16 mから外れて通り過ぎていた。

|区間|中継点 (m)|最初の通過時の最接近距離|その後の再計画|
|---|---|---:|---|
|バケツ②→③|`(1.55, -1.25)`|0.284 m|記録開始162.83秒以降、その中継点へ戻る経路|
|バケツ③→②|`(1.55, 0.15)`|0.222 m|188.24秒以降、その中継点へ戻る経路|

到達していない中継点が残るため、ロボットが先へ進んでもNav2が後方への経路を
作り直していた。曲率だけによる速度制限では、駆動遅れを伴う実際の曲がり方を
通過判定内に収められていなかった。

[記録の抜粋](bucket_gate_fixture_20260915.json)には初期経路、自己位置、
後戻りを指示する再計画、元JSONLのSHA-256を保存した。

## 変更

- `routes.yaml` の固定中継点・進入ゲート・退出ゲートを追従器にも読み込む。
  左右両フィールドの同じ位置関係に適用する。
- ゲートから0.35 m以内は**基準速度を0.20 m/s以下**にする。
  その手前も、0.30秒の応答遅れと設定加速度から必要な減速距離を計算し、
  軌道の速度計画へ組み込む。出力を境界で突然切り替える処理ではない。
- 固定ゲート位置付近を通る経路に適用するため、保存地点への移動にも効く。
  ゲートから離れた場所では、従来のプロファイル上限まで速度を上げられる。
- 中継点の通過判定0.16 m、指定目標、固定レーン、衝突監視、緊急停止は維持する。
  より低い速度プロファイルを選んだ場合、その上限を超えない。

設定は `config/routes.yaml` の `fixed_gate_tracking`。
通常の起動処理への接続とビルドを確認した。**実行中のプロセスには反映されず、
次回のシステム起動で有効になる。**

## 検証

### 記録経路を使った閉ループ再生

[実行スクリプト](../scripts/check_bucket_gate_replay.py)で、実際の追従制御、
RuntimeGuard、UARTの飽和、実測から求めた応答ゲインを使用した。
Nav2の元経路を区間ごとに保持し、通過半径に入らなければ中継点を残したまま
1秒ごとに再計画するモデルで比較した。

往復2方向×左右2フィールド×応答3条件の**12条件すべてで全中継点を通過し到達**した。
応答条件は、遅れ/一次遅れが0.10/0.08秒、0.20/0.12秒、0.30/0.15秒。
最後の条件では応答ゲインも10%増やした。位置・姿勢にも雑音を加えた。

|指標|修正後|
|---|---:|
|後戻り距離の最大値（目標方向のY軸への射影）|0.918 mm|
|サンプル時点のCAD車体余裕の最小値|15.13 mm|
|到達時間|20.21〜22.58秒|

比較側には最大1.053 mの後戻りと、未通過ゲートが残る例があった。
戻らずに通れた比較条件に対しては所要時間が増える。今回の設定は、
中継点を外す往復運動と狭い進入口での膨らみを抑えるための調整である。

結果と使用ファイルのハッシュは [再生結果](bucket_gate_replay_20260915.json)。
これはNav2のオンライン探索、センサー通信、自己位置推定、滑り、
ライブのCollision Monitorを再現する試験ではない。
CAD余裕はサンプル時点の値であり、実機での接触回避の保証には使わない。

```bash
source /opt/ros/jazzy/setup.bash
source ros2_ws/install/setup.bash
python3 scripts/check_bucket_gate_replay.py
```
