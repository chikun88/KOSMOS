# 回転中の高速移動の拡張（2026-09-16）

予測制御付きsprintの回転中速度予算を、条件付きで3.0から4.0 m/sへ引き上げた。
ROSパッケージをビルド済み。次回起動で反映する。実機の再起動・走行指令送信は行っていない。
4 m/sは指令の予算であり、実機速度4 m/sの達成を示す値ではない。

## 適用条件

- 既存の校正済みハードウェア・simultaneous・predictive_sprintの条件を満たす。
- 経路の全接線が、発進時の機体前後軸とほぼ一致する（内積の絶対値0.999以上）。
- 経路全体のCAD余裕からサンプル間の並進・回転による車体外周移動上界を引いても15 cm以上残る。
- 同一目標の再計画では発進時の機体方向を保持する。余裕や経路方向の条件を失ったら資格を取り消し、途中からの昇格はしない。

従来から35 cmの経路余裕で許可されていた開放経路の全速走行に加えて、
上記条件を満たす経路でも回転中の車輪予算を使えるようにした。
横・斜め発進や余裕の小さい経路には従来の予算を適用する。
加速度、停止距離、曲率制限、各輪UART上限10000、衝突監視は変更していない。

## 比較方法

保存済み25経路を遅れ0.20秒／応答0.12秒と遅れ0.30秒／応答0.15秒で再生する。
変更前に到着かつCAD余裕15 mm以上だった条件に対し、未到着、余裕15 mm未満、
0.15秒超の到着遅延を退行とする。以前から基準を満たさない条件は合格扱いしない。

別に、仮想の幅1.6 m・長さ30 mの直線通路で、前後左右4方向、姿勢変更±90度、
遅れ2条件の16条件を比較する。壁余裕は機体を囲む円の半径と最大横ずれから
保守的な下界を計算する。これは実フィールドの通路やライブ衝突監視の再現ではない。

一律4 m/sへ広げる候補では横発進の到着遅延が見つかったため採用しなかった。
[不採用候補の比較](faster_rotating_unrestricted_rejected_20260916.json)を保存している。
加速度を3から4 m/s²にする探索も、保存経路の到着遅延を検出した時点で中止し、採用していない。

モデルは低速で同定した応答ゲインを高速へ外挿しており、遅れは仮定値。
荷重・滑り・自己位置異常を再現していない。実走の改善は未確認。

## 最終コードでの結果

- [保存25経路・50条件](faster_rotating_sprint_20260916.json)：変更前に基準を満たす20条件で退行0。50条件すべて変更前後の結果が同一。この記録の短い経路では速度向上を確認していない。残り30条件は従来から基準未達。
- [仮想通路16条件](faster_rotating_corridor_20260916.json)：変更前に基準を満たす14条件で退行0。前後発進の8条件で到着時間が0.26〜7.69%短縮した。変更した条件の壁余裕下界は最低102 mm。
- 横発進8条件は変更前後で同一。そのうち2条件は従来から保守的な壁余裕基準未達であり、成功扱いしていない。
- 例：前進・姿勢+90度・遅れ0.30秒では、回転中最高速度2.793→3.179 m/s、到着15.96→14.97秒。これはモデル真値であり実測値ではない。
- 回転・予測・加速／制動・車輪合成・到着・校正の関連テスト246件成功。前後／横／斜め発進、余裕不足、再計画時の発進方向保持と昇格防止の検証を含む。
- `colcon build --symlink-install --packages-select omni_autonomy_next` 成功。

## 再現

```bash
source /opt/ros/jazzy/setup.bash
source ros2_ws/install/setup.bash
OPENBLAS_NUM_THREADS=1 python3 scripts/check_faster_rotating_sprint.py \
  --output /tmp/faster_rotating_sprint.json
OPENBLAS_NUM_THREADS=1 python3 scripts/check_faster_rotating_corridor.py \
  --output /tmp/faster_rotating_corridor.json
```

両スクリプトは変更前の3 m/s予算をメモリ内で再現し、現行コードと比較する。
ソース・設定・入力資料のハッシュを開始時と終了時に確認して記録する。ロボットへのI/Oはない。
