# 直近の低速走行と加速設定（2026-09-16）

通常balancedの並進加速度を0.85→1.80 m/s²、高速sprintを0.85→3.00 m/s²として、
実ローダー・制御・送信上限まで検証した。今回の作業開始時にsprint用の3.00設定と
加速／制動分離の変更が作業ツリーにあり、それを検証して通常モードへの適用も追加した。
precisionは0.85 m/s²。次回起動から適用。実走による改善・6 m/s達成は未確認。

## 直近ログで確認したこと

日本時間13:54:16開始 `20260916T045416.707583Z-b446e557` と、
13:22:20開始 `20260916T042220.528190Z-114477c8` の生JSONLを再解析した。
[監査JSON](acceleration_audit_20260916.json)に元データのハッシュ・各段の速度・
取得時刻の対応付け・欠落件数を保存した。demoは使っていない。

|実機セッション|計画ピーク|最終指令最大|約0.5秒の変位速度最大|UART最大|欠落件数|
|---|---:|---:|---:|---:|---:|
|13:54開始|0.943 m/s|0.871 m/s|0.849 m/s|3063 / 10000|5167|
|13:22開始|1.313 m/s|1.085 m/s|1.083 m/s|4080 / 10000|33005|

直近走行はsprint・倍率1.0だったが、保存されたrobot.yamlには加速プロファイルの指定がなく、
max_accel 0.85と従来のguard設定で走っていた。現在の3.0設定はその実走には適用されていない。
上流で1 m/s前後しか計画しておらず、モーター上限10000への飽和が主因ではない。
約6 mの曲がりと姿勢変更を含む経路では、加速以外にも旋回・曲率・終点制動が効く。

13:54の応答同定は旋回の励起不足で棄却。再生には直前13:22の応答ゲイン
(2.7044, 2.6262, 2.8142)を使った。欠落があるため校正値更新には用いていない。
変位速度も計測輪由来で、外部測定による真の速度検証ではない。
監査JSONのbudget内の加速度0.85はsmoother由来の従来計算であり、変更後sprintの加速度ではない。

## 適用する設定

|モード|並進加速度|guardの加速度上限|速度要求上限|
|---|---:|---:|---:|
|precision|0.85 m/s²|0.95 m/s²|2.0 m/s|
|balanced（起動時）|1.80 m/s²|2.10 m/s²|2.0 m/s|
|sprint|3.00 m/s²|3.30 m/s²|4.0 m/s|

加速設定の倍率は約2.1倍／3.5倍。これは実速度・所要時間の倍率ではない。
制御上の0→2 m/sの単純な立上がり時間は2.35秒→1.11秒／0.67秒となるが、
jerk・旋回・応答遅れ・制動区間等を除いた計算である。

- 軌道の前向き加速計算と出力の増速にプロファイル別加速度を使う。
- 減速・方向反転・横方向補正は独立した0.85 m/s²の予算を使う。
- 終点から逆算する制動計画、停止余裕、遅れの見積りも独立した制動予算を使用する。
- tracker statusに`acceleration_limit_m_s2`と`braking_limit_m_s2`を出力し、
  次のログで適用を確認できる。
- UART全輪上限10000、衝突監視、速度倍率、精密モードは既存条件を使用する。

この変更は通常のsimultaneous tracker経路が対象。trackerを使わないMPPI経路の
velocity_smoother加速度は0.85のまま。staged heading／後退の独自制限も残る。

## 38条件の比較

[再生スクリプト](../scripts/check_acceleration_replay.py)で、
[直近ログの2経路](acceleration_routes_20260916.json)と、空いた仮想直線を比較。
加速度0.85／1.8／3.0、応答遅れ0.20／0.30秒・一次遅れ0.12／0.15秒を組み合わせた。
[全結果](acceleration_replay_20260916.json)には使用ソースのハッシュを保存している。
速度・guard・制動条件は各比較で固定し、加速度だけを変えた。
従来ログをそのまま再現する比較ではなく、現在のコードで加速変更の影響を分離する比較である。

|経路・モード|従来0.85のモデル到着時間|採用加速度の到着時間|短縮率|
|---|---:|---:|---:|
|実記録6.04 m・sprint|11.05〜12.72秒|10.33〜11.98秒|5.8〜6.5%|
|実記録5.96 m・sprint|9.76〜11.66秒|9.18〜11.21秒|3.9〜5.9%|
|空いた4 m直線・balanced|5.90〜5.97秒|5.29〜5.37秒|10.1〜10.3%|
|空いた4 m直線・sprint|5.90〜5.97秒|5.02〜5.15秒|13.7〜14.9%|
|空いた8 m直線・sprint|7.64〜7.84秒|6.38〜7.21秒|8.0〜16.5%|

実記録経路の最高速は、加速3.0でも0.873〜0.946 m/sにとどまった。
曲がりと姿勢変更の速度制限を加速度変更だけで解消したとは言えない。
8 mの空いた仮想直線では、最高速2.39〜2.42→2.82〜2.84 m/s。
38条件すべて仮想終点へ到達したが、ライブNav2・RL・衝突監視・自己位置ジャンプ・
手動介入・荷重や滑りは再現しない。高速での応答は低速データからの外挿。

CAD余裕は6.04 m経路で95 mm。5.96 m経路・遅れ0.20秒では69→63 mmとなった。
同経路・遅れ0.30秒は変更前後とも余裕0で、全条件の安全性合格ではない。
実機衝突の証拠でもなく、遅れが大きい条件のモデル上の課題として残る。
