# 実走行ログを踏まえた加速度の連続化

実機の通常加速で、目標速度に達した瞬間に加速度を切り落としていた処理を修正した。
目標速度までに残った速度差から、ジャーク制限下で加速度をゼロに戻すための離散時間和を逆算する。
加速度を早めに抜くことで、巡航へ入るときの衝撃を減らす。

## 参照した実走行

実機 egg8 の ROS ログ3セッションを取得。実LiDAR、計測輪、モーターブリッジの起動を照合した。
時計がずれており、ログ名は `2026-07-29-01-29-37`、`01-52-37`、`02-34-17`。
日付順で上位だった9月7日のログは synthetic_scans を使ったシミュレーションであり、実走行として扱っていない。

- 到達記録85件。バケツ間の往復、退避、保存Aへの進入・後退を含む。
- 直近セッションでは操作速度倍率0.74。
- 速度比の警告161件、中央値1.43、範囲1.25〜3.15。
- この比は現在の上流指令と遅れた計測速度との比較。減速・下流制限でも大きくなり、駆動較正値の推定には使えない。
- 生の指令・実測速度時系列は保存されていないため、今回の比較結果は実機での速度・振動改善の実測値ではない。

ログから抽出したイベントと元ファイルのSHA-256は `field_log_evidence.json` に保存。
開始位置や目標切替が異なるため、経路別の所要時間をそのまま前後比較していない。

## 修正と検証

通常の一定速度への加速を、実機設定のRuntimeGuardに入力して比較した。
前方・斜め・横方向の3方向で次の結果となった。

|指標|変更前|変更後|
|---|---:|---:|
|並進ピークジャーク|80 m/s³|40 m/s³|
|旋回ピークジャーク|200 rad/s³|80 rad/s³|

直線2mの制御周期を実行し、RuntimeGuard・駆動の遅れ・一次遅れ・計測ノイズ・再計画を含むモデルで30条件を比較した。
応答倍率1.0〜3.2、遅れ0.12〜0.30秒、一次遅れ0.08〜0.15秒、3方向、操作倍率0.74/1.0。
最終指令の加速度変動量は全条件で約7〜16%低下。到達時刻差の中央値は0秒。
到達は位置15mm以内かつ実測速度25mm/s以内を0.5秒連続で満たすこととした。
詳細は `field_capture_validation.json`。CAD実経路や動的障害物を再現した試験ではない。

終点手前で位置ゲインを上げる高速化候補も比較したが、応答倍率・遅れの大きい条件で整定や滑らかさが悪化したため採用していない。
最高速度・操作倍率・停止距離の較正を引き上げた変更ではなく、速度をほぼ維持して加速度の不連続を減らす変更である。
急な目標変更・制限変更・緊急停止は別であり、あらゆる入力で厳密なジャーク上限を保証するものではない。

回帰テスト457件合格。新規試験は加速の最終周期までのジャーク、4方向・3周期、即時ゼロ停止、時刻付き記録の信号と時刻を検証。
既存の保存A後退、バケツ退出、目標切替、障害物・自己位置・通信異常の試験も含む。

## 次の実走行の記録

`python3 run.py record-run` を実行すると、通常の集計ログと時刻付きJSONLを `logs/` に保存する。
記録プロセスは購読のみで、移動指令を送らない。

- 追従器指令 `/cmd_vel_nav_smoothed`
- 衝突監視後 `/cmd_vel_collision_safe`
- 最終指令 `/cmd_vel_safe`
- 制御器が実際に使用する計測輪 `/wheel/odometry`
- 自己位置、追従器状態、安全状態

受信ROS時刻・単調増加時刻と、計測メッセージの元時刻を記録する。
生データは継続書込みし、メモリ内集計は各信号直近10万件までとする。
較正を断定していた警告文も、時刻を合わせて最終指令と実測を比較する案内に修正した。
大幅な高速化の定量評価は、この記録を伴う次の実走行が必要。
