# 行先指定後の発進待ち・Nav2起動待ちの修正

## 原因と変更

バケツへの接続経路のCAD検査をgoal_bridgeのROSコールバック内で同期実行していた。
退避位置のように現在位置が接続点になる経路では、自己位置の微小な揺れにより
キャッシュが使えず、毎回計算し直していた。計算中はNav2のGetState応答を
処理できず、計算直後の状態再確認で有効期限切れとなると、待機と再計算を繰り返す。

- 接続経路の計算を専用の1ワーカースレッドへ移し、ROSの応答処理を継続する。
- リクエストごとに経路を一度準備し、状態待ちや自己位置の微小変動で再計算しない。
  リトライでは現在位置から再準備する。行先変更・キャンセル後の旧計算結果は送信しない。
- 行先変更時は重い経路計算に先行して実行中のNav2ゴールをキャンセルする。
- 明らかに通れない接続候補は疎な点群で早期除外する。
  採用する接続候補は従来どおり全1 cmサンプルと同じ余裕条件を検査する。
- 保留処理の周期を200 msから50 msへ短縮する。
- 経路計算中はGUIへ「経路準備中」を表示する。
  実際にNav2が未準備の場合は「Nav2起動待ち」を維持する。

Nav2のライフサイクルがactiveで新鮮であること、および使用するアクションサーバーの
準備完了確認は維持している。速度・衝突監視の設定変更は行っていない。

## 計測・検証

同じ環境で退避位置付近の3点からバケツ③進入点への接続計算を実測した。
これは実機のクリックから発進までの時間ではなく、経路計算部分の時間。

| 項目 | 修正前 | 修正後 |
|---|---:|---:|
| 接続計算（3点） | 0.797–0.801秒 | 0.142–0.143秒 |
| 接続グラフ初期化 | 8.03秒 | 2.87秒 |

関連181テスト成功。左右フィールドの経路、長い計算中の状態待機、自己位置の微小変動、
行先変更、キャンセル、Nav2未準備時の送信抑止、元のCAD判定との一致を検証。
4パッケージのcolconビルド成功。

追加のアーキテクチャ検査では既存の角加速度設定の不整合が1件失敗：
`test_guard_dynamics_are_a_gate_around_the_shaping_stage_not_a_second_one`
（balancedのangular_accel=1.3に対しvelocity_smoother=2.0）。
今回変更した発進待ち処理とは別であり、この設定は変更していない。

ビルド済み。次回起動から反映される。実機走行・実際の発進時間は未検証。
