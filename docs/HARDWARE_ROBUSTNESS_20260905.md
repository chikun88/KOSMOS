# 2026-09-05 実機の遅れ・速度誤差に対する安定性の修正

実機向けの指令生成を担当する egg8PC の `omni_autonomy_next` を更新した。
今回の変更は「目標公差を一度通過する」ことと「目標付近に安定して停止する」ことを
区別する。物理モーターを使った走行試験は行っていない。

## 根拠と修正

実機ログ `logs/diagnose-chain-20260806-204616.log` には指令と計測輪速度の差がある。
ただし異なる時刻のピーク値の比なので、これを較正係数として適用することはできない。
`logs/drive-directions-20260807-1955.log` の較正試行は、最初の走行前に標準入力のEOFで終了している。
従って、`AUTO_UNITS_PER_MPS=7202` が実機で較正済みという証拠はない。

この不確かさを含む試験で、旧設定は到着判定を一度通っても振動や停止位置ずれが残った。
実際の `_build_trajectory` と `_tick` を呼び、計測雑音、20 Hz制御、1 Hz再計画、
駆動ゲインと遅れを含めて20秒走らせ、最後の5秒間の全サンプルが40 mm / 0.035 rad以内に
留まることを合格条件にした。

| 駆動ゲイン（指令に対する実速度比） | 無駄時間 | 一次遅れ時定数 |
|---:|---:|---:|
| 1.0 | 120 ms | 80 ms |
| 2.8 | 120 ms | 80 ms |
| 2.8 | 200 ms | 120 ms |
| 2.8 | 300 ms | 150 ms |
| 3.2 | 200 ms | 120 ms |

この5条件を3方向で試した15ケースは、**旧設定5/15成功、新設定15/15成功**。
障害物回避、実センサーの全誤差、任意の遅延やゲインを保証する試験ではない。

### 補正のかけすぎを抑える

| パラメーター | 旧 | 新 |
|---|---:|---:|
| position_gain | 2.4 | 0.8 |
| position_damping | 0.25 | 0.10 |
| yaw_gain | 1.6 | 1.0 |

軌道の速度を先行して与える方式は継続し、遅れて戻ってくる誤差への補正を弱める。
並進・旋回の速度上限を一律に下げる変更ではない。終点への収束に時間が増える場合はある。
単純な最短角度の補間を維持し、複雑な姿勢最適化は既定では有効にしない。

### 古い計測輪速度で予測し続けない

`velocity_timeout_sec=0.20` を追加した。自己位置が新しくても計測輪速度が古ければ、
追従器の指令をゼロにし `ODOMETRY_STALE` を出す。
メッセージの測定時刻を確認し、遅延した古いデータ、順序逆転・重複、非有限値、
20 msを超える未来時刻のデータで鮮度を更新しない。
速度フィルターは受信コールバック間隔ではなく測定間隔を使う。
欠落後の復帰はフィルターを新しい測定値で再開し、参照位置も現在位置に合わせ直す。

### 整定中の進捗と停滞を区別する

従来は角度の改善だけが整定の進捗に含まれていた。今回は終端での実測位置誤差が
最良値から10 mm以上改善したときも進捗として扱う。最良値は再計画をまたいで保持する。
一定半径の周回、同じ目標の繰り返し、雑音だけでは時間切れを無期限に延長できない。
半径60 mmの周回を1 Hzで再計画し続けてもゼロ指令で停止する回帰試験が成功した。

### 停止まで確認して到着とする

Nav2の `goal_checker` を `nav2_controller::StoppedGoalChecker` に変更し、
`stateful=false` とした。位置40 mm、角度0.035 radに加え、並進0.03 m/s以下、
旋回0.03 rad/s以下を確認する。向きを合わせる途中で位置がずれた場合も位置を再確認する。
配備ホストのプラグイン登録と、起動ログの実際のロードを確認した。
パラメーターの意味は [Nav2 Jazzyの公式仕様](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/core_servers/controller_server/controller_server_plugins/stopped_goal_checker/) に従う。

## 検証結果

- ROSパッケージとシミュレーションの299テスト成功。
  最後に追加した一定半径の周回テスト1件も成功、計300件。
- `colcon build --symlink-install --packages-select omni_autonomy_next` 成功。
- bacon6のゲートウェイ `ctest` 3件成功。両リポジトリの `git diff --check` 成功。
- 標準遅延での自由空間4区間比較では、単純補間の横方向誤差の最大値は13.0～15.3 mm。
  要求角加速度ピークは0.19～1.994 rad/s²。始動直後を除く出力角加速度制限の作動率は0%。
  これは固定進入レーンや障害物を含む実フィールドの安全余裕ではない。

独立ROS domain 91のモーターOFF合成デモによる統合試験を実施した。
計測輪とLiDARは合成データであり、以下の値は物理走行の実測ではない。
統合試験の詳細JSONはバックアップ内の `evidence/` に保存する。

| 内容 | 結果 | 指令開始から到達 | 到達2.5秒後の位置誤差 / 角度誤差 |
|---|---|---:|---:|
| 地点1→2 | SUCCEEDED | 8.470秒 | 約25.3 mm / 0.33度 |
| 地点0で180度回転、途中5秒停止 | SUCCEEDED | 13.253秒（停止込み） | 約0.6 mm / 0.89度 |
| 地点4→5、途中2秒停止 | SUCCEEDED | 17.694秒（停止込み） | 約17.8 mm / 0.001度 |

3試験とも、到達2.5秒後の合成オドメトリ速度は並進・旋回ともゼロ。
到着時点の観測速度も並進0.027 m/s以下、旋回0.029 rad/s以下だった。
位置・速度・到着通知は別々のROS購読で観測するため、厳密に同時刻の計測ではない。
立ち上がりに `ODOMETRY_STALE`、停止中や始動時に `STALE_COMMAND` が観測されるが、
復帰して到達した。旧版より到着時間が増える場合があり、今回は安定性と停止確認を優先した。

こちらの検証用プロセスだけを独立domainで起動・終了する。
