# 自己位置推定の計算と時刻

自己位置推定ノードは、ROS の受信・タイマー・サービス・結果確定を単一の
制御スレッドで実行し、ICP と再捕捉探索を一つの専用ワーカーで計算します。
センサー周期、ICP 要求周期、姿勢／健全性配信周期、鮮度期限は変更しません。
計算中の要求は一つにまとめ、次回は制御側で最新の入力を準備します。
過去の点群や取得要求を待ち行列に積みません。

ワーカーに渡す点群、初期姿勢、車輪姿勢、地図壁、設定は、コピーした
読み取り専用データです。ワーカーは ROS ノードや現在の設定を参照せず、
ICP と再捕捉の既存の幾何計算だけを行います。結果は ROS のガード条件で
制御側に返し、計算中に到着した車輪移動を反映してから補正を適用します。

初期姿勢の変更、フットプリントの変更、設定の正常な確定は世代番号を更新し、
変更前の計算結果を破棄します。設定を検証しただけの段階ではキャッシュを
変更しません。ほかの検証器が設定を拒否した場合も旧設定を維持します。
結果確定時には、その計算が実際に使った全スキャンの取得時刻を再検証します。
新しいスキャンが到着していても、古い入力で完了した計算を健全性の更新に
使いません。健全性の配信時にも現在のスキャン鮮度を確認します。
再捕捉探索中に車輪が動き始めた場合は、停止時に準備した再捕捉結果を破棄します。

ワーカー例外は制御側へ伝播します。終了要求は ICP の反復境界で確認し、
ワーカー終了を待ってから ROS のオブジェクトを破棄します。取消要求で
途中の計算結果を適用することはありません。OS や数値ライブラリ内の一回の
処理が停止した場合まで終了時間を保証する仕組みではありません。

実装前の接続済み ROS グラフでは、旧マルチスレッド実行器のディスパッチ
スレッドが一つの CPU の約 47–57%、ICP ワーカー側が約 14% を消費しました。
この測定を受けて実行方式を変更しています。測定環境は上位 cgroup に
4 CPU 分の割当制限があります。単体 ROS 回帰試験は受信継続、計算中の
リセット・設定・フットプリント変更、古い入力、要求の集約、例外、終了を
検証します。全経路の動作確認および実機の処理能力確認は別途必要です。
