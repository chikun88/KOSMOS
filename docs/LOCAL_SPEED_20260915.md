# スタート出口・バケツ付近の高速化

## 現在の設定：スタート出口3.50 m/s・バケツ入口1.00 m/s

画像の赤丸をスタート出口と解釈し、`fixed_departures.1.turn_speed_m_s` に
3.50 m/sを指定した。左右のスタート出口ゲートに局所上限を適用し、
バケツ入口は共通設定1.00 m/sを使う。再計画にも局所上限を引き継ぐ。
同じゲートに複数設定が重なる場合は低い方を使用する。

この変更は局所的な減速上限の変更であり、全体の2.0 m/s上限や車輪・曲率制限は
別途適用される。実速度3.50 m/sを達成する設定ではない。
次回起動から適用し、3.50 m/s設定の走行検証は未実施。

## 以前の設定：共通1.00 m/s

ユーザー指定により `fixed_gate_tracking.speed_m_s` を **0.24 → 1.00 m/s**
へ変更した。次回起動から適用。これは曲がり区間の上限であり、実際の速度は
曲率、車輪上限、加減速、衝突監視などでも制限される。
1.00 m/sでの走行検証は未実施。下記の比較結果は以前の0.24 m/s設定に限る。
入口0.30 m/s・中央曲がり0.50 m/sの組み合わせでは接触が再現されているため、
過去の結果を今回の設定の安全性の根拠にはできない。

## 以前の設定：0.24 m/s

`config/routes.yaml` の `fixed_gate_tracking.speed_m_s` を **0.20 → 0.24 m/s**
に変更した。スタート出口と固定バケツの狭いレーン入口で、急な曲がりを
検出した区間の速度上限を20%上げる。

中央通路の曲がり速度0.40 m/s、巡航上限2.0 m/s、手前・出口の減速保持距離
各0.25 m、応答遅れ0.30秒は既存値。到着制動、衝突監視、緊急停止も継続する。

## オフライン比較

[比較スクリプト](../scripts/check_local_speed_replay.py)は、既存の実測応答ゲイン、
追従器、RuntimeGuard、UART飽和、CAD車体検査を使う再生処理を呼び出す。
変更前後でゲート通過判定や他の速度条件は同じにして比較した。

- バケツ：記録経路の往復2方向。
- スタート：地点1 → 固定出口(-1.80, 4.10) → (-2.80, 4.10) → 地点2の構成経路。
- 左右フィールド、遅れ/一次遅れ0.10/0.08秒、0.20/0.12秒、0.30/0.15秒。
  最後の条件では実測応答ゲインをさらに10%増やした。

計18条件すべてで全ゲート通過・到達し、各条件で所要時間が短縮した。

|区間|変更前|変更後|同じ条件での短縮率|
|---|---:|---:|---:|
|スタート出口|9.76〜10.52秒|8.86〜9.41秒|7.5〜10.6%|
|バケツ往復の各方向|15.15〜16.56秒|13.39〜15.63秒|4.9〜12.0%|

サンプル時点の最小CAD余裕はスタート23.05 mm、バケツ15.13 mm。
各条件の余裕低下は5 mm以内、最終位置誤差は15 mm未満という比較基準を満たした。
詳しい結果は [JSON](local_speed_replay_20260915.json)。

入口0.30 m/s・中央曲がり0.50 m/sの案は、遅れ条件でCAD接触が再現され、
採用していない。
