# 4 m/s巡航時間の追加調整

sprintの並進加速度を3.00から3.30 m/s²に変更。RuntimeGuardのsprint加速度は
3.30から既存のhard上限3.50 m/s²へ変更した。起動時は既存どおりsprint。
加速の理論0→4 m/s時間は1.333→1.212秒。制動0.85 m/s²、曲率制約、
UART上限10000、障害物監視は維持する。precision/balancedは変更していない。

## 結果

- 加速・旋回・軌道追従・RuntimeGuardの関連テスト133件成功。
- omni_autonomy_nextのcolconビルド成功、インストール先の設定反映を確認。
- 保存2経路と仮想8/16 m直線について、遅れ0.20/0.30秒の計8条件を比較。
  8条件とも到達し、到着遅延0.15秒超またはCAD余裕15 mm未満への退行なし。
  保存経路の到着時間は0.04〜0.50秒短縮した。
- 単純な直線軌道計画では16 mで4 m/s巡航0.978→1.038秒、
  30 mで4.478→4.538秒。4/8 mでは変更前後とも4 m/s巡航なし。
- 応答モデルでは16 m直線の最高速は約3.74 m/s。
  保存経路では1.22〜1.71 m/sであり、全経路4 m/sは未達成。

比較は現在のguard 3.5を固定し、発進加速度だけ3.0/3.3としたもの。
計画上の巡航時間には実機の応答遅れ、終端寄せ、UART飽和を含まない。
応答モデルも低速の実記録からの外挿で、実機の高速走行確認ではない。
全移動で4 m/sを長時間維持するには、経路長・実際の制動能力・車輪出力が足りない。
今回の調整による延長は限定的で、超高速走行の達成とは扱わない。

次回起動に適用。稼働ノードの再起動や走行指令の送信は行っていない。
