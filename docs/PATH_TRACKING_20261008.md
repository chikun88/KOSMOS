# 3.5 m/sに向けた経路追従の修正（2026-10-08）

対象: `chikun88/KOSMOS`、変更前 `9a7593b`。
ユーザー指定は最高速度3.5 m/s、経路誤差をできるだけ小さくすること。
本変更はソフトウェアと数値モデルで検証する。実機へは接続していない。

## 修正内容

| 問題 | 変更 |
| --- | --- |
| 計画上の横加速度1.2 m/s²が実行側の補正予算0.85 m/s²を超え、曲線で膨らむ | 実行可能な横加速度に揃え、接線・横方向の加速度を合成して前後掃引する |
| 正しい名目速度でもP/D補正が曲線の速度上限を超える | 最終指令全体に経路上の速度制限を適用し、将来の曲がり角への制動距離を遡って確保する |
| 交差・近接する復路へ最近傍点が飛び、未走行区間を省略する | 同じ軌道を追従中は実測移動量から探索する弧長範囲を限定する。新軌道の初期対応付けは従来どおり |
| `cross_track`が経路からのずれではなく時間基準との距離を表示する | 互換項目を保持し、`cross_track_m`、`reference_error_m`、`along_track_error_m`、`observed_progress_m`を区別して記録する |
| 極低速経路の時間に人工的な速度下限が入り、終端時刻と位置が一致しない | 同じ加速度則から時間を計算し、速度ゼロで移動する実現不能な区間を拒否する。短い停止間移動には中点を確保する |
| 遅れ予測のEuler積分と指令切替の時刻丸めが高速旋回で数値ずれを生む | 指令の実時刻で積分区間を分け、一次遅れの解析解と回転座標での数値積分を使用する。小さい時定数にも計算量の上限を維持する |
| 投影・接線計算が制御周期ごとに同じ配列を作り直す | 不変の区間幾何を保存し、実測位置の投影を周期内で再使用する |
| CAD距離計算が毎回すべての壁を詳細検査する | 外形半径と距離上限を含む矩形で候補を厳密に絞る。詳細距離、25 mm基準、制動モデルは保持する |
| フィルター速度だけの静止判定が新しい実測運動を隠す | 段階移動の旋回・発進切替で、生の車輪速度も既存の静止基準に照合する |
| 受信キューの古いUDP返信が新鮮な通信状態に見える | カーネル受信時刻と連番を検証し、再送・順序逆転を拒否する。期限切れ後のPi連番再初期化は再認可を要求する |
| 車輪履歴外のLiDAR点を端点固定で補正し、走行中も未補正点群へフォールバックする | 実測履歴に覆われた点だけを補正する。不足時は同じscanを次の車輪受信で再試行する。初回車輪速度と取得時刻も静止判定に使用する |
| sprintの4 m/s設定が今回の目標と不一致 | Nav2、smoother、tracker、guardの並進要求を3.5 m/sへ揃える。UART上限10000と既存較正・制動減速度は保持する |

位置・姿勢の経路補間は変更していない。既存のCAD経路検査を維持するため、
折れ線の補間と平滑なフィードフォワード微分の小さい不一致は残る。
この変更だけで任意の角・自己交差経路の正確な追従を保証しない。

## 速度の意味

3.5 m/sはsprintの直進・横移動要求上限。既存較正でUART各輪9579/10000となり、
単軸では飽和しない。45度斜行のモデル上限は約2.475 m/sで、旋回にも車輪予算を使う。
曲率、停止距離、CAD検査、障害物、位置推定・通信の状態によって速度を下げる。
全経路を常時3.5 m/sで走る設定ではない。

加速3.3 m/s²、制動0.85 m/s²の場合、3.5 m/sからの理想制動距離だけで約7.206 m。
静止から加速して停止するには理想条件でも約9.062 mが必要で、通信・応答遅れ、
ジャーク、制動の余裕は別途加わる。実機の速度・停止距離を測定した数値ではない。

```bash
python3 scripts/performance_envelope.py
```

## 検証の区別と再現

ROS 2 Jazzy環境で4パッケージをビルドし、最終固定ソースで **Python 1816件、
BTのC++ 10件、gatewayのCTest 8件がすべて成功**した。構文・差分検査も成功。
tf2 core/wrapperは両方0.36.23で確認した。
[ソフトウェア検証の条件・結果・ソース指紋](SOFTWARE_VERIFICATION_20261008.json)を保存した。
初回全体試験で見つかった試験側の競合・不整合も修正した。無線送信の初回時刻記録前に
SIGSTOPする競合、DDSリセット待ちで期限切れとなる試験scan、較正設定の取得元、
実際の経路生成を通していない2点の停止間軌道が対象。製品の判定条件を緩めていない。

`scripts/benchmark_path_tracking.py`は本番の軌道構築・追従tick、RuntimeGuard、
bridge較正、UART飽和を使用する。曲線を一定の経路として保持し、途中で
現在位置から終点への直線へ差し替えない。経路誤差は独立の点対線分計算で測る。
到着には位置15 mm、姿勢0.015 rad、並進0.025 m/s、旋回0.025 rad/s以内を
0.5秒連続で満たすことを要求する。

空間内の数値再生であり、実ROSのスケジューリング、LiDAR、滑り、動く障害物、
実機I/Oを含まない。CAD付き条件も人工的な広い箱であり、実フィールドの全経路受入
ではない。計算時間の計測と仮想時間の運動再生も別である。

### 同じ3.5 m/s設定での変更前後比較

変更前・変更後とも同一の最終設定を使用し、速度設定変更の効果を混ぜずに比較した。
5経路、遅れ0.12/0.20/0.30秒、姿勢・CAD条件の計45条件を各版で再生した。
**両版とも45/45到着**で、到着前の制御失敗は0。経路上の精度は大きく異なる。

| 条件 | 最大経路誤差（前→後） | 平均到着時間（前→後） |
| --- | ---: | ---: |
| CADあり、姿勢一定の曲線6条件 | 1,180→76 mm | 8.32→9.02秒 |
| CADあり、姿勢を0.3 rad変更する曲線6条件 | 942→199 mm | 8.93→7.13秒 |
| CADなしで追従制御を分離した曲線6条件 | 1,651→385 mm | 9.39→7.33秒 |

24 mの直線・姿勢一定のCAD条件では、全3遅れ条件でモデル上の最高速度3.500 m/sに到達。
12 mの直線は約3.384〜3.449 m/s。停止余裕が必要なため、短い経路での速度保証にはならない。
到着時の15 mm条件は実機の絶対位置精度を意味しない。

一様な改善ではない。CADあり・半径3 m曲線・遅れ0.12秒では最大誤差39.9→70.8 mmに
増えた。その他6条件でも1〜2 mm程度の増加がある。姿勢一定の曲線では平均到着時間も
約0.71秒増えている。すべてを最速・誤差ゼロにした結果ではなく、既存制約内で大きな
逸脱を減らす変更として評価する。
[90再生の全結果・悪化条件・ソース指紋・再現手順](PATH_TRACKING_BENCHMARK_20261008.json)
を保存した。

python3 scripts/benchmark_path_tracking.py --geometry open_box --goal-yaw .3 \

python3 scripts/benchmark_clearance_broad_phase.py --baseline-ref 9a7593b \

## 残る実機・全経路の確認

既存のMPPI形式の代用モデルも同じseed `20261007`、49経路で再実行した。
変更前後とも46到着、3接触予測（2→4、4→7、6→3）で、全経路受入は失敗。
この代用モデルは本変更の本番追従器を実行しないため、追従器の改善評価と混同しない。
[比較結果と設定指紋](LEGACY_MODEL_20261008.json)を保存した。

```bash
python3 -m simulation.run_campaign --episodes 49 --random-episodes 0 \
  --seed 20261007 --output /tmp/current-field-model.json
```

実機の3.5 m/s、経路上のミリメートル精度、全フィールドの到着は未確認。
実測した遅れ・応答、計測輪較正、滑り・荷重、LiDAR有効距離、制動距離を含む
[ACCEPTANCE.md](ACCEPTANCE.md)の受入が必要。
MCUの独立watchdogと位置制御軸の物理的停止も、リポジトリ外のfirmware・実機で確認する。
修正の反映とこれらの受入完了は別であり、「すべての問題を解消」「完全動作」とは判定していない。
