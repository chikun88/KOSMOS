# 同時旋回の加速度配分改善：検証結果

回転しながら移動する主方式に、区間ごとの加速度配分を追加した。
経路・目標姿勢・最高速度の設定は同じ。旋回に必要な加速度を計算して、
固定配分による余分な減速を減らす。旋回が支配的な短距離では従来の余裕を維持する。
方針・計算式は `SIMULTANEOUS_DEVELOPMENT_20260908.md` を参照。

## ソフトウェア検証

- 回帰試験 **508件合格**。今回追加の17件は、区間途中の並進・旋回加速度、
  角速度、短距離の余裕維持、通常旋回での加速度の有効利用を確認。
- ROS 2パッケージの分離ワークスペースでのビルド成功。
- 既存の保存A後退、目標切替、無線地点指示、障害物・自己位置・通信異常の試験を含む。

## 遅れ・ノイズを含む前後比較

実際の追従器とRuntimeGuardのコードを、20 Hz制御・100 Hz駆動モデルで比較。
計測ノイズ、0.12〜0.30秒の遅れ、0.08〜0.15秒の一次遅れ、応答倍率1.0〜3.2、
操作倍率0.74/1.0を使用。4 cm〜3 m、旋回0/±90/180°を含む6経路×5条件。
各条件の前後で同じ乱数を使い、0.5秒継続して位置15 mm・姿勢0.02 rad・
並進速度0.025 m/s・角速度0.04 rad/s以内に入る時刻を計測した。

|指標|変更前|変更後|
|---|---:|---:|
|整定成功|30/30|30/30|
|平均整定時刻|5.800秒|5.742秒|
|2 m移動＋90°旋回、応答倍率1・遅れ0.12秒|5.93秒|4.18秒|

平均の短縮は約1.0%。時刻差の中央値は0秒、最良は1.75秒短縮、最悪は0.05秒増加。
大半の条件はほぼ同じであり、特定の一例の約30%短縮を全走行の改善率とはしない。
上記2 m旋回の最終指令の角加速度変動量は140.43から111.75へ約20%減少した。
この変動量は走行開始から整定確認までの累積値であり、全条件の振動改善率ではない。
変更後の末尾3秒の最大誤差は、全条件中で位置1.77 mm・姿勢0.0136 rad。

比較データは `evidence/simultaneous_20260908/final-comparison.json`。
`scripts/compare_simultaneous.py` は変更前のクラスと軌道構築処理も別に読み込み、
同じ条件を再現する。元ソースは同じ証拠ディレクトリに保存する。

このモデルは実機較正値へのフィッティングでも、CAD障害物・動的障害物を含む
全走行系でもない。最高速度の増加や実機振動の低下を測定した結果ではない。

## ROSフィールド試験・適用

実フィールドのCAD・機体形状を使い、ROS domain 91・localhost限定・
`demo:=true motors:=false` で以下の到達と正の掃引余裕を確認した。

|区間|所要時間|到達位置誤差（自己位置）|疑似真値の最小掃引余裕|
|---|---:|---:|---:|
|地点1→4：同時旋回を含む|13.798秒|13.77 mm|41.34 mm|
|地点4→5：バケツ間|16.450秒|10.72 mm|28.79 mm|

いずれも `SUCCEEDED`。疑似真値の到達位置誤差はそれぞれ14.63 mm・11.42 mm。
これは変更後の疎通・幾何検証であり、ROS全系での前後速度比較ではない。
初回の1→4試験は速度平滑化ノードのライフサイクル通信が成立せず、走行前の
`WAITING_FOR_NAV2` で終了した。同じ設定で再試験した結果を上表に採用した。
起動成功率まで改善したとは判断しない。

適用先は egg8PC の `/home/egg8/Desktop/omni_autonomy_next`。
変更前ハッシュの照合とバックアップを行う配布スクリプトを使用する。
制御器の変更は次回システム起動から有効。GUIの方式表示は
「旋回しながら移動（標準）」になる。

今回、新しい制御での実機走行や最高速度引上げは実施していない。
通常の実走行では記録を取り、同じ地点・速度倍率で今回の改善を比較する。
