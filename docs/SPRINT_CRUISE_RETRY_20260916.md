# 最新実経路での回転中速度改善

## 変更と適用

sprintの回転中予算に、中間の1.30 m/s設定を追加した。
前回は、残り経路全体で35 cm以上の追従余裕がある経路だけ高速化し、
それ以外は1.05 m/sのままだった。今回の変更では実際の記録経路にも改善が出た。
**改善はオフライン再生での結果であり、変更後の実走・4 m/s達成は未確認。**

- 開けた経路：従来どおり4 m/s要求の車輪予算。
- 経路全体の車体余裕から、サンプル間の並進・回転移動の上界を引いても
  25 mm以上ある経路：回転中1.30 m/s、車輪19.449 rad/sの中間予算。
- それ以外、CAD不明、非有限値、balanced／precision：従来の回転中予算。

中間予算は経路の開始時に判定する。同じ目標への再計画では資格を取り消せるが、
途中から新しく許可しない。これにより、再計画で通過済みの狭い区間が消えた直後に
加速する現象を防いだ。途中許可の候補は一部経路でCAD余裕が悪化し、採用しなかった。
25 mmは幾何判定の残余で、実機の高速安全性や任意の遅れへの保証ではない。

UART上限10000、終点制動、角加速度、曲率、衝突監視は維持する。
適用確認は `/trajectory_tracker/status` の `local_linear_limit_m_s=1.3` と
`local_wheel_budget_rad_s=19.449` で行える。

## 最新実走ログの原因

対象：`20260916T060012.684309Z-b385e3ae`（15:00:12 JST開始）。
[監査](latest_speed_retry_audit_20260916.json)、[抽出14経路](latest_speed_retry_routes_20260916.json)。

- sprint、加速3.0 m/s²、制動設定0.85 m/s²、速度倍率1.0は適用されていた。
- 追従中2105メッセージのうち1423件（67.6%）で局所上限1.05 m/s、
  車輪15.709 rad/s。これは時間比率ではなく、記録されたメッセージ数の比率。
- 計画最大2.062 m/s、最終指令最大2.204 m/s、約0.5秒変位速度最大2.107 m/s。
  最大値が出る区間はあるが、回転を伴う多数の区間は低い予算のままだった。
- UART最大6376 / 10000。出力飽和が今回の低速の主因ではない。
- 記録欠落15211件。計測輪変位と低速応答フィットを実機性能の保証には使用しない。

## 実経路の比較結果

最新14経路と前回9経路、それぞれ応答遅れ0.20秒／0.30秒の計46条件。
実装のtracker・guard・UARTとCAD形状を使用。各記録の低速ゲインを用い、
速度制御以外の条件を揃えて比較した。全条件がモデル上で到着した。

|最新経路（plan sequence）|長さ|到着時間の短縮|最高速度の上昇|
|---|---:|---:|---:|
|17958|5.97 m|6.7〜8.0%|10.6〜22.6%|
|26054|3.43 m|2.4〜3.5%|9.0〜13.1%|
|89760|8.39 m|8.7〜9.9%|18.4〜19.5%|

最新14経路中3経路で改善し、残る11経路の結果は同一だった。
前回9経路では2経路で到着時間3.1〜12.5%短縮、残る7経路は同一。
今回の変更で全経路が速くなったとは言えない。

46条件中、従来から到着かつCAD余裕15 mm以上だった16条件について、
新たな余裕不足・未到着・0.15秒超の到着遅延は0件。
残る30条件は従来からCAD余裕の条件を満たさず、今回の変更後も同じ問題が残る。
個別の最小余裕は改善経路でも増減する。例えば89760の遅れ0.20秒では
120→114 mm。全経路の安全性合格や実機衝突の証拠とは扱わない。

ライブ衝突監視、自己位置の飛び、手動介入、実負荷・滑りは再現していない。
最新実走で遅かった問題に対する実装改善だが、実機での効果は次回測定が必要。

結果：[最新28条件](sprint_cruise_latest_replay_20260916.json)、
[前回18条件](sprint_cruise_previous_replay_20260916.json)。ソースハッシュ付き。
