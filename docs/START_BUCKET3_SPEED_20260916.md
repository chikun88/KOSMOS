# スタート→バケツ3の高速化比較（未適用）

今回比較した候補では、遅れを含めて到着時間と障害物余裕を両立する改善を
確認できなかったため、運用コード・速度設定は変更していない。
「超爆速化」は未達成。実機への走行指令は送信していない。

現在の起動プロファイルはsprint、速度要求上限4 m/s、発進加速度3.3 m/s²。
この短い曲線経路では上限値より曲率・制動・位置追従の影響が大きい。

## 比較条件と結果

設定済み地点1（スタート）から地点5（バケツ3）まで、出口・通過・進入ゲートを
直線で結んだ仮想経路を使用した。実際のNav2経路の再現ではない。
既存の追従器・RuntimeGuard・UART出力モデルに、低速実測から外挿した応答と
遅れ0.20秒／応答時定数0.12秒、遅れ0.30秒／時定数0.15秒を与えた。
左フィールドのみ。ライブ衝突監視、滑り、自己位置異常は再現しない。

|候補|到着秒（遅れ0.20秒）|到着秒（遅れ0.30秒）|不採用理由|
|---|---:|---:|---|
|現設定・位置ゲイン1.6|9.24|8.81|比較基準|
|位置ゲイン2.0|9.04|8.17|遅れ0.30秒でCAD接触予測|
|位置ゲイン2.5|9.03|15.80|遅れ0.30秒で接触予測・後戻り|
|位置ゲイン3.0|8.66|15.23|余裕不足、遅れ0.30秒で接触予測・後戻り|
|中央通過点のyを0.60→0.00|9.21|8.82|遅れ0.30秒で接触予測|
|最初の外側通過点のyを2.05→3.00|9.38|9.22|遅延・接触予測|
|最初の外側通過点のyを2.05→3.50|9.53|9.98|遅延・接触予測|

現設定のCAD最小余裕は各条件で48.6 mm／21.4 mm。
50 ms間隔のサンプル評価であり、サンプル間も接触しない保証ではない。
到着は位置誤差15 mm以内・姿勢誤差0.015 rad以内・低速状態を0.5秒維持した
区間の開始時刻。遅れの大きい条件が早く到着する結果も、実機改善を示すものではない。

[全14条件と入力・ソースハッシュ](start_bucket3_speed_candidates_20260916.json)。
大幅な短縮を進めるには、現設定のこの区間の実走ログから、実際に制限している
曲率・衝突監視・追従誤差と制動応答を切り分ける必要がある。

## 再現

```bash
source /opt/ros/jazzy/setup.bash
source ros2_ws/install/setup.bash
OPENBLAS_NUM_THREADS=1 python3 scripts/check_start_bucket3_speed.py \
  --output /tmp/start_bucket3_speed_replay.json
```

実行中のソース変更はエラーにする。保存時と異なるコードでも再比較できるため、
出力には実行時のハッシュを記録する。ソフトウェアの比較であり実機検証ではない。
